# LabGear

Небольшой учебный pet-проект — система бронирования и учёта лабораторного оборудования.

Проект позволяет вести список оборудования, создавать заявки на его бронирование, отслеживать выдачу и возврат, а также регистрировать неисправности.

## Что умеет приложение

- Регистрация и авторизация пользователей.
- Разделение пользователей по ролям: студент, техник, администратор.
- Просмотр и поиск оборудования.
- Добавление и редактирование оборудования.
- Создание заявок на бронирование.
- Проверка доступности оборудования на выбранное время.
- Подтверждение и отклонение заявок.
- Выдача и возврат оборудования.
- Регистрация неисправностей.
- Учёт технического обслуживания.
- Просмотр статистики и отчётов.

## Запуск проекта

Для запуска потребуется установленный Docker Desktop (или Docker Engine с Docker Compose).

Python и PostgreSQL устанавливать отдельно не нужно.

### 1. Клонирование репозитория

```bash
git clone <REPOSITORY_URL>
cd labgear_backend
```

### 2. Настройка переменных окружения

Создать `.env` на основе примера:

```bash
cp .env.example .env
```

При необходимости изменить параметры подключения к базе данных и настройки приложения.

### 3. Запуск

```bash
docker compose up --build -d
```

При первом запуске:
- создаётся контейнер PostgreSQL;
- запускается FastAPI;
- выполняются миграции базы данных;
- добавляются демонстрационные пользователи и оборудование;
- запускается frontend на Nginx.

### 4. Открытие приложения

| Раздел | Адрес |
|---|---|
| Веб-интерфейс | http://localhost:8080 |
| API | http://localhost:8000 |
| Swagger | http://localhost:8000/docs |

## Обновление после git pull

Если репозиторий уже склонирован:

```bash
git pull
docker compose up --build -d
```

Docker пересоберёт изменённые образы и перезапустит необходимые контейнеры.

Файл `.env` повторно создавать не нужно.

## Полезные команды

Посмотреть запущенные контейнеры:

```bash
docker compose ps
```

Посмотреть логи приложения:

```bash
docker compose logs -f api
```

Посмотреть логи frontend:

```bash
docker compose logs -f frontend
```

Перезапустить приложение:

```bash
docker compose restart
```

Остановить контейнеры:

```bash
docker compose stop
```

Остановить и удалить контейнеры:

```bash
docker compose down
```

### Сброс тестовых данных

В проекте не используется постоянный именованный Docker volume для PostgreSQL.

Поэтому при выполнении:

```bash
docker compose down
docker compose up --build -d
```

контейнер базы данных создаётся заново, после чего выполняются миграции и повторно загружаются демонстрационные данные.

**Важно:** созданные вручную пользователи, бронирования и другие записи при таком сбросе не сохраняются.

## О проекте

Проект разработан в учебных целях для практики работы с Python, FastAPI, PostgreSQL и Docker.
